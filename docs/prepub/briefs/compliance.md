Read `docs/prepub/briefs/_common.md` first and follow it. Your name is `compliance`. Output file: `docs/prepub/reviews/compliance.md`. Scratch folder: `~/gdn-prepub/agents/compliance/`.

## Role

You review public communications at an asset manager, and you have seen students lose offers over a careless post about a listed company. Read `docs/LINKEDIN_POST.md` exactly as it will be pasted into LinkedIn. Then read the README's first screen and footer, the dashboard's static text (`site/index.html`, and the strings in `site/app.js`), the note's header, disclaimer and footer (`report/note.html`; the PDF at `output/GD_research_note.pdf` is printed from it, and you can read its text with `pypdf` from `~/gdn-prepub/venv/bin/python` if that interpreter exists, otherwise read the HTML), the workbook's sheet names and labels, `docs/INTERVIEW_NOTES.md`, `docs/RESUME_BULLETS.md`, `LICENSE`, and the GitHub description and topics (`gh repo view --json description,repositoryTopics,homepageUrl`).

## Questions you must answer by name

1. **The post as a public statement by a student about a listed company.** Is there any investment advice, recommendation, rating, price target, or wording a reader could take as one? Is there a disclaimer line (student project, not investment advice)? Is there a disclaimer of affiliation with General Dynamics and Gulfstream? Should there be? Quote what is there and what is missing.
2. **Trademark use.** "Gulfstream", "General Dynamics", "GD", model names (G280, G700, G800), "FAA", "LinkedIn", "GitHub", "Motley Fool", "MarketBeat". Is any name used in a way that implies endorsement or affiliation, in the project title, the repository name, the dashboard title, the page `<title>`, the favicon or the hashtags?
3. **Accuracy of every self-description.** "I locked", "I tested", "I counted", "I checked", "held out", "preregistered", "locked on GitHub before GD reported". For each first-person claim in the post, the README lead, the note and the resume bullets, find the evidence in the repository that it is true as worded. In particular: the repository was private when the 2026Q3 release was published, so what exactly can the owner claim about the lock being verifiable, and does any surface call it a "public lock"? (`config/calendar.json` has a `"public"` key; read how `src/gdn/report.py` and `src/gdn/note.py` use it.) Who ran the job that made the lock: the owner's Mac or a GitHub workflow (`git log --format='%h %an %ad %s' --date=iso | grep -i lock | head`)? Does the wording match?
4. **LinkedIn's limits and rendering.** Count the post's characters with Python (the limit is 3,000). Quote the first 210 characters (the desktop feed's cut before "see more") and the first 140 (the mobile cut). Do those lines carry the result and what the project is? Does LinkedIn render Markdown (it does not): is there any Markdown syntax, a bare URL that will unfurl badly, or a line break that will look wrong?
5. **Hashtags and links.** Is any hashtag a ticker or a company name that could read as stock promotion (`#GeneralDynamics`)? Are the links the right ones, and will each resolve once the repository is public and GitHub Pages is on? Check each URL in the post and the README now (WebFetch) and say what it returns today.
6. **README and note headers and footers.** Author name, date, disclaimers. Is the author named consistently? Is there a date on the note and is it right? Does the note carry "not investment advice" and a no-position statement on every page of the PDF or only on the first? Does the README carry any disclaimer at all? Does the dashboard?
7. **Third-party content and data rights.** Does the repository store transcript text (Motley Fool, MarketBeat) or article text beyond short quotes? Look at `data/guidance.csv`, `report/claims.json`, `docs/build/claims_*.json`, `docs/build/*.csv`. Is FAA data redistribution fine (it is public domain; say what the repository stores)? Does `LICENSE` cover the code only, and does it say so? Does any stored file carry a person's name from the FAA registry (aircraft owners) in a way that matters?
8. **Personal information and housekeeping.** Email addresses, home paths (`/Users/...`), tokens, the SEC user-agent string, anything about the owner's machine, in tracked files (`git ls-files | head -200`, `git grep -n -I -E '/Users/|@<personal domains>' | head -40`). Internal build notes in `docs/build/`: is anything there embarrassing, stale, or about tools and prompts the owner may not want public?
9. **Tone and voice.** Is the post in plain first person? Does it use any hype word (elevate, seamless, leverage, robust, cutting-edge, game-changer, delve, unlock, harness, journey, landscape, powerful, insights)? Any em dash or en dash in prose on any public surface?
