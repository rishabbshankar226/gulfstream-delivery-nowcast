    How it was tested

      When the registry has not finished posting

      Each test quarter's own registrations are cut a set number of days before the quarter ends, while the four quarters before it stay whole, so the count falls and nothing rescales it. It shows how fast the miss grows when a quarter's registrations post late. It is not a model of a live lock, which is made weeks after the quarter ends.

      On Gulfstream's own registration

      Jets registered to Gulfstream itself with no delivery event yet, by model: aircraft in flight test, completion or resale, and registrations held for jets not yet airworthy.

      The figures as a table

      What it means for GD

      Aerospace from the delivery estimate is the delivery estimate × trailing Aerospace revenue per delivery, services included: a mechanical estimate. The defense segments use the same quarter last year scaled by trailing growth, a rule from my study of other contractors; applying it to GD is an assumption.

      Method

      1. Each Gulfstream jet in the FAA registry that my scope rule keeps gets a delivery date: a customer's registration, or an export off Gulfstream's own registration, whichever comes first. One type code of a newer large-cabin jet falls outside the rule; the README's Limitations name it and give its size.
      2. Those dates are counted in GD's fiscal quarters, by cabin size.
      3. The count is scaled by how many deliveries GD reported per registration over the four quarters before.
      4. The quarters from 2017Q1 to 2019Q4 set the rule; the 26 quarters from 2020Q1 to 2026Q2 test it against GD's guidance pace (my construction, not a figure GD publishes: its full-year delivery outlook less the deliveries already reported, spread by each quarter's usual share of the year) and two simple rules of thumb.
      5. Each live quarter's estimate is locked on GitHub the day before GD reports, and kept whether it hits or misses.
